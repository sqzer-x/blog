지속가능한 백수생활을 위해 기존에 온프레미스 환경에서 구동중이던 서비스들을 하나씩 서버리스로 마이그레이션 중이다.
사실 서버리스라는 정의의 개념만 인지하고 있는 상태였고 환경이나 구축, 솔루션, 연동 같은 복잡한 구조까지는 알지 못하여 근 한달동안 짬짬히 공부하며 온프렘에서 서버리스로 마이그레이션을 진행하였다.

온프레미스 환경이 관리, 통제 목적으로는 용이하다는 장점이 있어 개인적으로 온프렘 환경을 선호하지만 확실히 온프렘 환경은 인적, 환경적 여유가 있어야 지속가능한 시스템인거 같다.
최근들어 온프렘 환경이 더 각박해진건 사실이다. 치솟는 전기값, 메모리, 스토리지 값, 퍼블릭 클라우드 인스턴스 비용(심지어 얘는 달러로 받아서 값은 2년전이랑 똑같은 모델인데 환율때문에 2배 더 비싸게 내고 있음), 도메인 비용 등등.
보수적인 늙은이 엔지니어한테는 온프렘이 마음이 편하지만 어쩔수가 없음...

덕분에 서버리스 환경과 솔루션들에 대해 공부할 수 있었고 생각보다 이론은 간단하지만 각각의 서비스에 맞는 솔루션들이 분산되어 있어 관리나 구성은 확실히 어려웠다.
물론, AWS같은 대형 서비스를 이용하면 편하겠지만 아무래도 비용이...

그래도 무료로 체험하고 공부할 수 있다는것 만으로도 큰 장점이라 도전해 보았고 제일 만만한 이 블로그 부터 서비리스 환경으로 옮겼고 아직까지는 큰 문제가 없는거 같다.

사용한 솔루션은 다음과 같다.

- Deploying: Vercel
- Backend: Supabase
- Redis: Upstash
- DNS: Cloudflare
- Domain: Spaceship
- Version Control: Github
